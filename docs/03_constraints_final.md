# Финальный набор ограничений

Дополнение базовых ограничений из дня 2 более сложными проверками
CHECK. Файл содержит итоговый набор ограничений по каждой таблице.

## 1. Сводная таблица ограничений

| Таблица | Поле | Ограничение | Обоснование |
|---|---|---|---|
| products | name | CHECK (length(name) > 0) | наименование не может быть пустым |
| products | price | CHECK (price > 0 AND price < 1000000) | цена не может быть отрицательной, нулевой или чрезмерно большой |
| stock_items | quantity | CHECK (quantity >= 0) | количество не может быть отрицательным |
| order_items | quantity | CHECK (quantity > 0) | количество в заказе всегда больше нуля |
| order_items | price | CHECK (price > 0) | цена позиции в заказе всегда больше нуля |
| users | login | CHECK (length(login) >= 3 AND length(login) <= 20) | логин разумной длины: от 3 до 20 символов |
| sizes | value | CHECK (value > 20 AND value < 50) | размеры обуви в разумном диапазоне |
| orders | order_date | CHECK (date(order_date) IS NOT NULL) | дата должна быть в формате ISO 8601 |

## 3. Пояснения

### products.name

Пустое наименование не имеет смысла — модель должна быть
идентифицирована хотя бы строкой. `length(name) > 0` отсекает
пустые строки.

### products.price

Цена не может быть нулевой или отрицательной. Верхняя граница
(миллион) защищает от случайного ввода лишнего нуля.

### stock_items.quantity

Количество на складе не может быть отрицательным — это
физически невозможно. Ноль допустим (товара временно нет).

### order_items.quantity

В заказе не может быть нулевого количества — если позиция
добавлена, значит, заказана хотя бы одна единица.

### order_items.price

Цена позиции в заказе не может быть нулевой или отрицательной —
это историческая цена на момент оформления.

### users.login

Слишком короткий логин (1–2 символа) неудобен и небезопасен;
слишком длинный (больше 20) — избыточен. Оптимальный диапазон
3–20 символов.

### sizes.value

Размер обуви в разумном диапазоне: больше 20 и меньше 50.
Отсекает отрицательные и явно ошибочные значения (например,
100 или -5).

### orders.order_date

Дата заказа должна быть корректной строкой ISO 8601.
Функция `date()` в SQLite возвращает NULL, если строка не является
корректной датой. `CHECK (date(order_date) IS NOT NULL)`
обеспечивает это.

## 4. Применение ограничений

Все перечисленные ограничения добавлены в DDL-скрипт
`src/db_init.py` при создании таблиц. База пересоздана с новыми
ограничениями.

Проверка работы: `python -m src.db_test_constraints`.
