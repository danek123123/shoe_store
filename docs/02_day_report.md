## Принятые решения и их обоснование

### Типы данных

- Все идентификаторы (PK и FK) — `INTEGER`.
- Строковые поля — `TEXT`.
- Дата заказа — `TEXT` в формате ISO 8601, потому что SQLite
  не имеет отдельного типа для даты.
- Размеры обуви — `INTEGER` (в нашем проекте размеры целые;
  при дробных размерах подошёл бы `REAL`).
- Цена — `REAL` (возможны копейки). Для строгих финансовых
  расчётов лучше `NUMERIC`, но в учебной схеме достаточно `REAL`.

### Ограничения

- **UNIQUE на login** — вход выполняется по логину; дубликат
  сделает невозможным однозначное определение пользователя.
- **NOT NULL на last_name, first_name** — обязательные
  атрибуты пользователя.
- **NULL на middle_name** — отчество есть не у всех.
- **CHECK (price > 0)** — цена не может быть нулевой или
  отрицательной.
- **CHECK (quantity >= 0)** в `stock_items` — количество
  не может быть отрицательным.
- **CHECK (quantity > 0)** в `order_items` — в заказе
  не может быть нулевого количества.
- **DEFAULT datetime('now')** на `orders.order_date` —
  дата заказа проставляется автоматически.
- **DEFAULT 0** на `stock_items.quantity` — по умолчанию
  товар отсутствует на складе.
- **UNIQUE (product_id, size_id)** — одна модель одного
  размера встречается в таблице один раз.
- **ON DELETE RESTRICT** для `users.role_id`,
  `stock_items.size_id`, `orders.user_id`,
  `order_items.item_id` — защита от потери ссылочной
  целостности.
- **ON DELETE CASCADE** для `stock_items.product_id`
  и `order_items.order_id` — удаление родителя удаляет
  дочерние записи, не имеющие самостоятельного смысла.

### Схема именования

Имена таблиц — во множественном числе (`roles`, `users`,
`products`); имена полей — в единственном (`name`, `price`);
идентификаторы — с суффиксом `_id`. Все имена в нижнем
регистре, snake_case. Зарезервированных слов SQL не используется.
