# Проверка схемы на соответствие требованиям

Проверка, что схема БД покрывает все функциональные требования
и права пользователей из описания предметной области.


## 1. Покрытие функциональных требований

| Требование | Таблица | Поле | Операция |
|---|---|---|---|
| В каталоге хранится актуальное количество товарных позиций | `stock_items` | `quantity` | SELECT, UPDATE |
| Для каждой модели сохраняется изображение | `products` | `image_path` | SELECT, INSERT, UPDATE |
| Пользователь выбирает одну или несколько пар обуви | `order_items` | `item_id`, `quantity` | INSERT, UPDATE, DELETE |
| Просмотр списка заказов с датой и ФИО клиента | `orders`, `users` | `order_date`, `last_name`, `first_name` | SELECT с JOIN |
| Управление заказами | `orders`, `order_items` | `order_id`, `status` | INSERT, UPDATE, DELETE |

## 2. Покрытие ролей пользователей

### 2.1. Неавторизованный пользователь

Просмотр каталога без фильтрации.

| Таблица | Поле | Операция |
|---|---|---|
| `products` | все поля | SELECT |
| `stock_items` | `quantity` | SELECT |
| `sizes` | `value` | SELECT |

### 2.2. Авторизованный пользователь

Каталог с фильтром, сортировкой, поиском; оформление заказа.

| Таблица | Поле | Операция |
|---|---|---|
| `products` | `name`, `category`, `subcategory`, `manufacturer`, `price` | SELECT с WHERE / ORDER BY |
| `stock_items` | `quantity` | SELECT, UPDATE |
| `order_items` | `item_id`, `quantity`, `price` | INSERT, UPDATE, DELETE |
| `orders` | `user_id`, `order_date` | INSERT |

### 2.3. Менеджер

Всё, что авторизованный, плюс просмотр и управление заказами.

| Таблица | Поле | Операция |
|---|---|---|
| `orders` | все поля | SELECT, INSERT, DELETE |
| `order_items` | все поля | SELECT, INSERT, DELETE |
| `users` | `user_id` | SELECT |

### 2.4. Администратор

Всё, что менеджер, плюс редактирование заказов.

| Таблица | Поле | Операция |
|---|---|---|
| `orders` | `order_date`, `user_id` | UPDATE |
| `order_items` | `quantity`, `price` | UPDATE |

## 3. Сводная таблица требований

| № | Требование | Реализация в БД |
|---|---|---|
| 1 | Хранение количества товарных позиций | таблица `stock_items`, поле `quantity` |
| 2 | Изображение для каждой модели | таблица `products`, поле `image_path` |
| 3 | Выбор нескольких пар в заказ | таблица `order_items` + FK на `stock_items` |
| 4 | Просмотр списка заказов | таблица `orders` + JOIN с `users` |
| 5 | Управление заказами | INSERT / UPDATE / DELETE в `orders` и `order_items` |

## 4. Проверка полноты схемы

- ✅ Все пять функциональных требований покрыты.
- ✅ Все четыре роли имеют доступ к нужным таблицам.
- ✅ Дополнительных сущностей вводить не требуется.
- ✅ Итоговая сумма заказа **не хранится** — вычисляется при
  выборке `SUM(quantity * price)` из `order_items`.

Схема полная и соответствует требованиям.
