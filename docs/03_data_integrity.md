# Проверка целостности данных

Документ описывает стратегии удаления для всех внешних ключей
и результаты их практической проверки.

## 1. Стратегии удаления по внешним ключам

| Таблица | Поле | Ссылается на | ON DELETE | Обоснование |
|---|---|---|---|---|
| users | role_id | roles.role_id | RESTRICT | нельзя удалить роль, если есть пользователи с этой ролью |
| stock_items | product_id | products.product_id | RESTRICT | нельзя удалить товар, если есть его товарные позиции |
| stock_items | size_id | sizes.size_id | RESTRICT | нельзя удалить размер, если он используется в позициях |
| orders | user_id | users.user_id | RESTRICT | нельзя удалить пользователя, у которого есть заказы |
| order_items | order_id | orders.order_id | CASCADE | при удалении заказа удаляются все его позиции |
| order_items | item_id | stock_items.item_id | RESTRICT | нельзя удалить товарную позицию, если она вошла в заказ |

## 2. Проверка PRAGMA foreign_keys

В функции `get_connection()` (файл `src/db_init.py`) выполняется:

    PRAGMA foreign_keys = ON

Без этого ограничения FOREIGN KEY в SQLite не работают — они
включены по умолчанию только в некоторых СУБД, а в SQLite
отключены.

## 3. Результаты практической проверки

| Проверка | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|
| Удаление пользователя с заказами | ошибка | FOREIGN KEY constraint failed | пройден |
| Удаление роли с пользователями | ошибка | FOREIGN KEY constraint failed | пройден |
| Удаление товара с позициями | ошибка | FOREIGN KEY constraint failed | пройден |
| Удаление размера, используемого в позициях | ошибка | FOREIGN KEY constraint failed | пройден |
| Удаление товарной позиции, вошедшей в заказ | ошибка | FOREIGN KEY constraint failed | пройден |
| Удаление заказа с позициями | каскадное удаление позиций | позиции удалены | пройден |

## 4. Вывод

Все шесть внешних ключей настроены корректно. Стратегии
RESTRICT и CASCADE работают так, как задумано:

- RESTRICT защищает от потери данных, связанных с удаляемой
  записью;
- CASCADE удаляет дочерние записи, которые не имеют смысла
  без родительской.

PRAGMA foreign_keys = ON включён, без него проверки не работали бы.

## 5. Полная проверка после изменений (шаг 62–67)

Скрипт: `src/db_check_all.py`
Команда: `python -m src.db_check_all`

### 5.1. CHECK-ограничения

| Проверка | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|
| Товар с ценой -100 | ошибка | CHECK constraint failed: price > 0 AND price < 1000000 | пройден |
| Товарная позиция с quantity -5 | ошибка | CHECK constraint failed: quantity >= 0 | пройден |
| Позиция заказа с quantity 0 | ошибка | CHECK constraint failed: quantity > 0 | пройден |
| Логин из двух символов | ошибка | CHECK constraint failed: length(login) >= 3 | пройден |
| Размер 100 | ошибка | CHECK constraint failed: value > 20 AND value < 50 | пройден |

### 5.2. FOREIGN KEY-ограничения

| Проверка | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|
| Удалить роль с пользователями | ошибка | FOREIGN KEY constraint failed | пройден |
| Удалить пользователя с заказами | ошибка | FOREIGN KEY constraint failed | пройден |
| Удалить товар с позициями | ошибка | FOREIGN KEY constraint failed | пройден |

### 5.3. Каскадное удаление

| Проверка | Ожидаемый результат | Фактический результат | Статус |
|---|---|---|---|
| Удалить заказ с позициями | позиции удалены автоматически | позиции удалены | пройден |

### 5.4. Вывод

Все ограничения работают корректно. База защищена от некорректных
данных и от потери ссылочной целостности. Каскадное удаление
позиций заказа работает автоматически.
